# 领域文档

工程类技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读这些

- **`CONTEXT.md`**（仓库根目录）—— 项目的领域术语和概念
- **`docs/adr/`** —— 阅读与当前工作领域相关的 ADR

如果这些文件不存在，**直接继续**。不要报告其缺失，也不要建议立即创建。`/grill-with-docs` 技能会在术语或决策真正确定时延迟创建它们。

## 文件结构

单一上下文仓库（大多数仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表中定义的词汇

当你的输出涉及某个领域概念（issue 标题、重构方案、假设、测试名称），请使用 `CONTEXT.md` 中定义的术语。不要偏离到术语表明确避免的同义词。

如果你需要的概念还不在术语表中，这是一个信号——要么你在引入项目不使用的语言（重新考虑），要么确实存在空白（记录下来以备 `/grill-with-docs` 使用）。

## 标记 ADR 冲突

如果你的输出与已有 ADR 矛盾，请显式指出，而非静默覆盖：

> _与 ADR-0007（xxx）矛盾——但值得重新讨论，因为……_
